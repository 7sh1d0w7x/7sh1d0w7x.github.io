The sysctl settings that actually matter (and three that don't)

2026-10-11 · Linux hardening · 3 min read

I ran my own auditor (state-witness) on a machine I'd already hardened. It flagged four sysctl checks. Two were real. Two were noise. That gap is the whole point.

The two that matter

kernel.kptr_restrict = 0        # kernel pointers visible in /proc
kernel.yama.ptrace_scope = 0    # any process can ptrace another

kptr_restrict should be 1 (or 2). At 0, kernel addresses leak through /proc — free information for an exploit chain.

yama.ptrace_scope should be 1. At 0, any process running as you can attach to another (read memory, steal secrets, inject). That's how a compromised browser tab reaches your SSH agent.

The two that are noise (on this box)

net.ipv4.ip_forward = 1        # "expected 0"
net.ipv4.conf.all.rp_filter = 0 # "expected 1"

Both were set by libvirt (for VM NAT), not by me. On a host running VMs or Docker, ip_forward=1 is correct — flagging it is a false positive. Good hardening tools check the effective state and the context, not just the number.

Fix the real ones

# /etc/sysctl.d/99-hardening.conf
kernel.kptr_restrict = 1
kernel.yama.ptrace_scope = 1

sudo sysctl --system   # apply
sysctl -n kernel.kptr_restrict kernel.yama.ptrace_scope   # verify

The takeaway

A hardening checklist that fires on everything is useless — you stop reading it. What you want is: what does this host actually enforce, and is that a real problem here? Two real fixes beat forty warnings.
